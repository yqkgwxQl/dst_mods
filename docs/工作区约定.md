# 工作区约定

> 这个仓库同时是 DSH 的工作区。本文件规定「什么东西放哪、谁在什么时候收」。
>
> 违反约定的后果不是报错，而是三个月后这里变成第二个 `wd`——458 MB、299 个顶层条目、没人说得清哪个能删。

## 一、四个层级，职责互斥

| 层 | 位置 | 放什么 | 进 git | 生命周期 |
|---|---|---|---|---|
| 完整记录 | `E:\...\DeepSeekHarness\home\sessions` | 每次会话的原始日志（zstd JSONL） | — | 永久，由 harness 管理 |
| 成品知识 | `docs\` | 手册、约定、说明 | ✅ | 永久 |
| 过程产物 | `_scratch\<日期>-<任务>\` | 解压、比对图、一次性导出 | ❌ | 任务结束清 |
| 待删备份 | `_trash\` | 删之前的缓冲 | ❌ | 一周后真删 |

**判定口诀**：

- 需要「重放整个对话」→ 去 `home\sessions` 搜（用 `search-sessions.mjs` / `dump-session.mjs`）
- 需要「以后照着做」→ 写进 `docs\`
- 只服务「这一次任务」→ 扔 `_scratch\`

> **本仓库不存会话日志。** `home\sessions` 是唯一事实源，再存一份就是重复且更差。

## 二、临时文件的唯一入口

所有中间产物只允许出现在：

```
_scratch\2026-11-07-github初始化\
_scratch\2026-11-07-swap包排查\
```

三条格式要求：

1. **`_scratch\` 根目录下不允许直接放文件**，必须先建一层子目录
2. **一次任务一个子目录**，不要把两次任务的东西混在一起
3. **目录名以日期开头**，便于按时间清理

## 三、三条使用规则

1. **落点唯一**：中间产物只写 `_scratch\`，不写仓库其他任何位置
2. **命名可追溯**：`日期-任务名`，让人一眼看出哪次留下的
3. **生命周期明确**：任务结束就清；值得留的**提炼成结论**写进 `docs\`，原始产物不搬

## 四、两条硬性禁止

1. **禁止往 `mods\`、`docs\`、`tools\` 写临时文件**——这三个目录是「要长期存在的东西」
2. **单次任务超过 50 MB 的中间产物，任务结束立刻删**——需要时重新生成即可（例：解压游戏源码用 `tools\prepare_refs.ps1`）

## 五、谁在什么时候做

| 时机 | 动作 | 谁 |
|---|---|---|
| 会话开始 | 列出 `_scratch\` 残留，问是否清理 | AI |
| 任务进行中 | 临时产物只写本次任务的子目录 | AI |
| 任务结束 | 清理本次任务的子目录；结论提炼进 `docs\` | AI |
| 每周 / 体积超限 | 跑 `tools\clean_scratch.ps1` | 人 |
| 改完任何 doc | 跑 `tools\check_docs.ps1` | AI |

## 六、`clean_scratch.ps1` 用法

```powershell
.\tools\clean_scratch.ps1                      # 预演：只列出，不删
.\tools\clean_scratch.ps1 -OlderThanDays 3     # 删除 3 天没动过的
.\tools\clean_scratch.ps1 -All                 # 全部清掉（会二次确认）
.\tools\clean_scratch.ps1 -All -MoveToTrash    # 先移进 _trash\，不直接删
```

它同时会检查「`_scratch\` 根目录有没有散落文件」——有就报出来，这是最常见的违规。

## 七、为什么不用 `%TEMP%`

1. **写权限不稳定**：沙箱对系统临时目录的访问时好时坏（本机曾因临时目录被清理导致沙箱整体不可用）
2. **路径不可预期**：`%TEMP%` 下混着几十个程序的垃圾，出事找不到
3. **清理不可控**：可能被系统清理工具随时删掉，任务中途丢失

放在工作区的 `_scratch\` 里，路径可预期、权限有保障、清理有脚本。

## 八、仓库边界

```
F:\zhongzhuan\dst_mods\        ← 工作区根 = 仓库根
├─ mods\        源码，进 git          ← 禁写临时文件
├─ docs\        手册与约定，进 git     ← 禁写临时文件
├─ tools\       工具，只 .ps1 进 git   ← 禁写临时文件
├─ refs\        游戏源码，不进 git
├─ _scratch\    过程产物，不进 git      ← 唯一临时区
├─ _trash\      待删备份，不进 git
├─ .gitignore
├─ README.md
└─ LICENSE
```

`mods/docs/tools` 是「要存在的东西」，`_scratch/_trash` 是「要消失的东西」，`refs` 是「可重建的东西」。

## 九、各类产物的落盘位置

| 产物 | 放哪 | 理由 |
|---|---|---|
| 单次测试报告 | `_scratch\<日期>-test-<mod>\` | 一次性的，看过就删 |
| 值得长期留的测试记录 | `docs\测试记录\` | 提炼后的结论 |
| **基线快照** | `docs\baseline\<mod>\` | **必须持久**——要参与下一次 diff，放 `_scratch` 会被清掉 |
| 原始日志副本 | `_scratch\<日期>-test-<mod>\logs\` | 体积大，用完删 |
| 集群配置备份 | `_trash\<日期>-cluster-backup\` | 预留回滚，确认无误后再真删 |
| 一次性的资源包 / 解压产物 | `_scratch\<日期>-<任务>\` | 大件，任务结束立刻删 |

**两个例外必须记住**：基线（`docs\baseline\`）和提炼后的测试记录（`docs\测试记录\`）**只能进 `docs\`，不能进 `_scratch\`**——它们要跨会话、跨机器存活。

## 十、与测试手册的关系

| 文件 | 只管 | 不碰 |
|---|---|---|
| **本文件（工作区约定）** | 物理世界：文件放哪、活多久、谁清理、仓库长什么样 | 怎么测 |
| `MOD测试手册.md` | 方法论：怎么测、判据、故障排查、工具怎么用 | 文件放哪 |

判断标准：这句话是在说「放哪里」还是「怎么做」。前者写进本文件，后者写进手册。

交叉引用约定：

- 手册提到落盘位置 → 指向本文第九节
- 本文提到测试流程 → 指向手册
