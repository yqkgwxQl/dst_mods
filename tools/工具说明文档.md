# tools —— 本机工具目录

存放 mod 开发用的脚本与第三方工具。**第三方二进制不入库**（`tools/app`、`tools/cli`、`tools/gui` 在 `.gitignore` 里），换机器时需要重新下载。

## 目录结构

```
tools/
├─ 工具说明文档.md         本文件
├─ 社区工具资料.md         ktools / Spriter / STex 等社区资料
├─ scripts/               自己写的 PowerShell 脚本（入库）
├─ official/              Klei 官方 Mod Tools 源码子集（本地，不入库）
├─ app/                   GUI 程序（不入库）
├─ cli/                   命令行工具（不入库）
└─ gui/                   小工具（不入库）
```

## 本地脚本（`scripts/`）

| 脚本 | 用途 | 什么时候跑 |
|---|---|---|
| `check_changes.ps1` | 列出工作区新增/删除/修改，并按类别给出同步建议 | **每次提交前**，第一步 |
| `sync_annotated.ps1` | 把精简版 `.lua` 同步进 `setting/annotated/` | 改完代码后 |
| `check_docs.ps1` | 检查文档结构、链接、必备文件、工具路径 | 改完文档后 |
| `check_anim_duration.ps1` | 检查动画 zip：条目、build/symbol 名、frame 几何、duration、atlas 尺寸；可和参考 zip 对比锚点 | 改动画 / 用 DST Mod Tool 导出 zip 后 |
| `prepare_refs.ps1` | 从游戏包解压 `refs/other_reference/scripts` | 换机器 / 游戏更新后 |
| `clean_scratch.ps1` | 清理 `_scratch/` 下的任务临时目录 | 每周 / 体积超限时 |

### 用法

在仓库根目录执行：

```powershell
# 改动盘点
powershell -ExecutionPolicy Bypass -File tools\scripts\check_changes.ps1

# 同步注释存档
powershell -ExecutionPolicy Bypass -File tools\scripts\sync_annotated.ps1

# 文档检查
powershell -ExecutionPolicy Bypass -File tools\scripts\check_docs.ps1

# 解压游戏源码（换机器时）
powershell -ExecutionPolicy Bypass -File tools\scripts\prepare_refs.ps1

# 清理临时目录
powershell -ExecutionPolicy Bypass -File tools\scripts\clean_scratch.ps1
```

## 常用流程

### 提交前

```text
check_changes.ps1 → sync_annotated.ps1 → check_docs.ps1 → git add / commit
```

详细清单见 `docs/文档同步清单.md`。

### 换机器

```text
下载第三方工具到 app/ cli/ gui/
→ prepare_refs.ps1 解压游戏源码
→ 按 docs/本机环境.local.md 校正路径
```

### 动画相关

- 打包 scml：`tools\cli\pyscripts\cli.py <file.scml>`
- 解包 zip：`tools\cli\pyscripts\cli.py <file.zip>`
- 检查动画 zip：`tools\scripts\check_anim_duration.ps1`
  - 全量扫描：`powershell -File tools\scripts\check_anim_duration.ps1`
  - 单个文件：`... -Zip mods\...\anim\xxx.zip -ExpectBuild xxx`
  - 对比锚点：`... -Zip 新.zip -RefZip 参考.zip`
  - 检查项：zip 条目、build/symbol 名、frame x/y/w/h、duration、atlas 尺寸、anim.bin 是否存在
- 贴图转换：`tools\cli\stex\stex.exe compress / decompress`
- **注意**：`cli.py` 编译 scml 会忽略 `<object x/y/scale>`；手持武器、跟随 FX 需要自定义锚点时，用 DST Mod Tool 导出（见「常见坑：build 的锚点与对齐」）

## 常见坑：build 的锚点与对齐

手持武器、跟随 FX 这类 build，图片最终画在哪由 **frame + pivot** 共同决定，不是只改 frame 就行。

- 在 **DST Mod Tool** 里把图片拖到**十字中心**，让工具自动生成 pivot 和 frame
- 武器和光晕要使用**同一个摆放位置/锚点**，`FollowSymbol` 的偏移才能是 `0, 0, 0`
- 不要手动改 `build.xml` 的 `Frame` 去凑位置：pivot、uv、顶点不会跟着同步，越补越偏
- `cli.py` 编译 scml 时会**忽略 `<object x/y/scale>`**，frame 仍按图片原点/居中生成；需要自定义位置时，用 DST Mod Tool 重新导出
- 已知案例：`blade_glow_fx` 用 DST Mod Tool 把光晕对齐到武器锚点后，光晕才正确覆盖剑身

## 维护约定

1. 新增**自己写的**脚本放 `scripts/`，并在上表登记用途与用法
2. 第三方二进制放 `app/`、`cli/`、`gui/`，**不要提交**；Klei 官方源码放 `official/` 仅本地参考，同样**不入库**
3. 新增第三方工具时，在本文件补一行说明和来源
4. 更新 `official/` 时，同步 `tools/official/README.md` 里的来源仓库与 commit
5. 脚本移动位置后，同步更新 `docs/` 与 `README.md` 里的路径引用
